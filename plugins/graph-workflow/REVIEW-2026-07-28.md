## 发现的问题

### G-001 · high · marketplace 漏登 graph-workflow

- **类别**: 规范一致性 / manifest
- **描述**: 根 `.codebuddy-plugin/marketplace.json` 的 `plugins[]` 只列了 dotnet-work / agentic-workflow / skill-radar,**graph-workflow 完全缺席**。`install-codebuddy.js` 在 `Updating marketplace manifest` 步骤会覆盖目标 marketplace,但源 `marketplace.json` 没有该条目 → CodeBuddy 用户通过 marketplace 搜不到此插件,版本号也不会同步(`bump-version` 的 marketplace 派生站点缺失)。
- **涉及文件**: `.codebuddy-plugin/marketplace.json:1-83`(plugins 数组无 graph-workflow 项)
- **建议修复**: 补一条 graph-workflow-codebuddy 条目,name/description/version/source/category/author/homepage/license/keywords 字段对齐其他条目;version 取 `0.1.0`。

### G-002 · high · trae / qoder / qwencode install 脚本不认 graph-workflow

- **类别**: 缺失能力 / 规范一致性
- **描述**: `install-codebuddy.js` / `install-zcode.js` / `bump-version.js` 的 `PLUGINS` 数组已含 `graph-workflow`,但 `install-trae.js` / `install-qoder.js` / `install-qwencode.js` 的 `PLUGINS` 仍是 `['dotnet-work', 'agentic-workflow']`。三平台 `--plugin graph-workflow` 直接报 `Unknown plugin`。AGENTS.md 明确要求三平台支持(graph-workflow 无 `.trae-plugin/` / `.qoder-plugin/` / `.qwen-plugin/` 平台 manifest,也无对应 `trae/` / `qoder/` / `qwencode/` agents 目录)。
- **涉及文件**: `scripts/install-trae.js:22`、`scripts/install-qoder.js:22`、`scripts/install-qwencode.js:42`
- **建议修复**: **STOP 线触发**——补齐三平台需要:① 3 套平台 manifest(`.trae-plugin/plugin.json` / `.qoder-plugin/plugin.json` / `.qwen-plugin/qwen-extension.json`);② 3 套 agents 目录(trae/qoder/qwencode 各 5 个 agent 文件,frontmatter 按平台适配);③ 3 个 install 脚本 PLUGINS 数组追加。跨 6+ 文件新建 + 引入新平台支持。**待人工确认是否本期补齐三平台**,还是先在 install 脚本里给出明确"暂不支持"提示。

### G-003 · high · loop-state 目录未被 gitignore

- **类别**: 规范一致性 / 数据安全
- **描述**: `scripts/loop-task.sh:17-18` 和 `graph-run.sh:17-18` 都 `mkdir -p "$SCRIPT_DIR/loop-state"` 写入任务状态文件(task-<ts>.json),`loop-helpers.sh:34` 还写 `.loop-marker`。但根 `.gitignore` 和插件目录都未忽略 `loop-state/` → 任务运行后会产生 `loop-state/task-*.json` 和 `.loop-marker` 污染工作树,容易被误 commit。对比:兄弟插件 agentic-workflow 的 `.loop-cli/state/` 同样未忽略,但那里 state 是有意管理的产物;graph-workflow 的 loop-state 是运行时临时产物,语义不同。
- **涉及文件**: 根 `.gitignore`(无 `loop-state` 条目);`plugins/graph-workflow/scripts/loop-task.sh:17`、`graph-run.sh:17`、`loop-helpers.sh:34`
- **建议修复**: 根 `.gitignore` 追加 `loop-state/` 和 `.loop-marker`。**STOP 线评估**:改根 `.gitignore` 是单文件追加,不破坏既有契约,不触发 STOP。

### G-004 · high · graph-task.md 路径 bug

- **类别**: 文档
- **描述**: `commands/graph-task.md` 第 40 行写 `bash .codebuddy/statectl.sh graph-next`,但正确路径是 `scripts/statectl.sh`(见 `state-schema.json` 引用、其他 commands、agents body 全用 `scripts/statectl.sh`)。`.codebuddy/` 是 CodeBuddy 运行时安装目录,不是插件源路径。用户照此执行会 `No such file`。
- **涉及文件**: `plugins/graph-workflow/commands/graph-task.md:40`
- **建议修复**: `.codebuddy/statectl.sh` → `scripts/statectl.sh`。单行修复。

### G-005 · medium · graph-run.sh / loop-task.sh 非 MOCK 退出信息误导

- **类别**: 代码质量
- **描述**: 两脚本在非 MOCK 分支(`graph-run.sh:162-166`、`loop-task.sh:103-108`)打印"等待编排者执行"后直接 `break`,跳出 while 循环。但此时 `final_reason` 仍为空,循环后逻辑(L212-214 / L154-156)会把 `final_reason` 设为 `ABORT: 达到 MAX_ITER 上限`——**与实际不符**(实际是第 1 轮就 break 了,根本没到 MAX_ITER)。用户看到的退出原因是误导性的"达到上限",而非"已交给编排者,等待外部驱动"。
- **涉及文件**: `scripts/graph-run.sh:162-166` + `212-214`;`scripts/loop-task.sh:103-108` + `154-156`
- **建议修复**: 非 MOCK break 前设一个明确的 `final_reason`(如 `"HANDBACK: 已启动编排者,等待外部驱动"`),或单独处理该路径的退出信息。**STOP 线评估**:改 2 个脚本共 2 处,局部修复,不触发 STOP。

### G-006 · medium · 无 README

- **类别**: 文档 / 缺失能力
- **描述**: 插件根无 `README.md`。兄弟插件 skill-radar 有 113 行 README(说明用途/架构/路由)。graph-workflow 的设计(Loop + Graph 双档位、外层脚本硬约束 + 内层三角色、version=1/2 区分)比 skill-radar 更复杂,却没有任何入口文档。新用户只能靠读 `commands/*.md` 和 `state-schema.json` 拼凑全貌。
- **涉及文件**: `plugins/graph-workflow/`(缺 `README.md`)
- **建议修复**: 新增 `README.md`,覆盖:插件定位、/loop-task vs /graph-task 选择、三角色协作图、状态文件 schema 要点、硬约束参数(MAX_ITER/BUDGET_S/STALL_LIMIT/VERIFY_CMD)、安全红线摘要。

### G-007 · medium · AGENTS.md 未登记 graph-workflow

- **类别**: 规范一致性 / 缺失能力
- **描述**: 工作区 `AGENTS.md` 在 `## dotnet-work`、`## agentic-workflow`、`## skill-radar` 三节分别登记了对应插件,但**完全没有 `## graph-workflow` 节**。AGENTS.md 是工作区的 single source of truth,新人/agent 读它会漏掉 graph-workflow 的存在和路由规则。`bump-version.js` 已经认 graph-workflow,说明它该被登记。
- **涉及文件**: `AGENTS.md`(无 graph-workflow 节)
- **建议修复**: **超出本次约束**——任务约束明确"仅在 `plugins/graph-workflow/` 和根 `scripts/` 内操作",改 AGENTS.md 超范围。**标注待人工补登记**,不在本轮修。

### G-008 · low · hook 字段枚举与 schema 重复定义

- **类别**: 代码质量 / 可维护性
- **描述**: `hooks/validate-state-write.js:14-17` 硬编码了 `VALID_STATUSES` / `VALID_PHASES` / `VALID_TASK_TYPES` / `VALID_REVIEWS`,这些与 `scripts/state-schema.json` 的 enum 值重复定义。schema 改了 enum,hook 不会自动跟。存在 drift 风险(例如 schema 加一个新 status,hook 会误拒)。
- **涉及文件**: `plugins/graph-workflow/hooks/validate-state-write.js:14-17`
- **建议修复**: hook 启动时读 `state-schema.json` 提取 enum(用 `require` + jq 风格的 JSON 解析)。或至少加注释标明"与 state-schema.json 同步"。**STOP 线评估**:改为动态读取 schema 属于行为变更,先加同步注释 + drift 自检,保守处理。

### G-009 · low · commands 无 version frontmatter

- **类别**: 版本一致性
- **描述**: `commands/{graph-task,loop-task,loop-review}.md` 只有 `description` frontmatter,无 `version` 字段。`bump-version.js` 注释提到会同步 SKILL.md frontmatter,但 commands 不在其列。兄弟插件 agentic-workflow 的 commands 同样无 version(一致),所以这不是 drift,是设计选择。**低优先,记录不改**。

### G-010 · low · validate-state.js 不支持 graph-workflow schema

- **类别**: 缺失能力 / 规范一致性
- **描述**: 根 `scripts/validate-state.js` 是 agentic-workflow 专用(version=1 coding/ralph-pipeline,version=2 ralph-graph),字段(prompt/max_iterations/tasks/nodes/active_set 等)与 graph-workflow 的 `state-schema.json`(task_id/objective/iteration/phase/graph/node_states)**完全不同**。AGENTS.md 的 "State validation" 节只示范了 agentic-workflow 的三个 state 文件,没提 graph-workflow。graph-workflow 的状态校验目前只靠 `hooks/validate-state-write.js`(G-008 的子集校验),没有独立 CLI 校验工具。
- **涉及文件**: `scripts/validate-state.js`(不支持 graph-workflow)
- **建议修复**: **STOP 线触发**——要么扩展 validate-state.js 支持 version=1/2 的 graph-workflow 分支(改公共工具行为),要么新建 `plugins/graph-workflow/scripts/validate-state.sh`。前者改公共脚本影响其他插件,后者新增文件。**待人工确认方向**。

## 缺口分析

与兄弟插件相比,graph-workflow 的能力缺口:

| 维度 | agentic-workflow | skill-radar | dotnet-work | graph-workflow | 缺口 |
|------|------------------|-------------|-------------|----------------|------|
| 平台 manifest | zcode+codebuddy+trae+qoder+qwen | zcode+codebuddy | zcode+codebuddy | **仅 zcode+codebuddy** | 缺 trae/qoder/qwen 三平台(G-002) |
| marketplace 登记 | ✅ | ✅ | ✅ | **❌** | G-001 |
| README | ❌ | ✅ | ❌ | **❌** | G-006(比 skill-radar 滞后) |
| AGENTS.md 登记 | ✅ | ✅ | ✅ | **❌** | G-007 |
| 状态校验工具 | ✅ validate-state.js | — | — | **仅 hook 子集** | G-010 |
| skills/ 目录 | ✅(scope-drift 等) | — | ✅(4 skills) | **❌** | graph-workflow 无可复用 skill,三角色硬编码在 agents 里。设计选择,非缺陷 |

**核心结论**: graph-workflow 是 4 个插件里平台覆盖最窄、文档最薄、工作区登记缺失最多的一个。功能设计(Loop+Graph 双档位、声明式图拓扑、Anti-Lazy 熔断)本身扎实,但**生态接入不完整**:装不进 trae/qoder/qwen,marketplace 搜不到,AGENTS.md 不认识它。
